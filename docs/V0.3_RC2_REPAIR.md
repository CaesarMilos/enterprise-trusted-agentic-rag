# V0.3.0rc2 逻辑修复说明 / Reliability Repair Notes

## 1. 文档撤销 / Document revocation

在索引返回 Chunk ID 后，`get_retrievable_chunks` 使用数据库最终校验：

```text
tenant 匹配
+ Document.status == READY
+ Document.active_version_id == Chunk.document_version_id
+ Source.is_active == true
```

因此删除重建失败或旧索引尚在服务时，`PENDING_DELETE` 文档也不再进入问答和引用。

## 2. Worker 心跳与 fencing / Lease heartbeat and fencing

`attempt_count` 每次领取递增。当前代次的 token 为：

```text
(tenant_id, job_id, lease_owner, attempt_count)
```

`JobLeaseGuard` 使用独立 Session 定期续租。Chunk 替换、质量指标、任务终态和索引最终激活在同一副作用事务内验证 token 与未过期租约。心跳数据库异常时按“不能证明仍持有所有权”处理，旧 Worker 停止后续写入。

## 3. 索引并发激活 / Concurrent activation

每个 BuildPlan 冻结 `expected_active_index_id`。激活事务先对租户行执行无变化 UPDATE：PostgreSQL 获得行锁，SQLite 提前获得写锁。锁定后再比较当前 ACTIVE，不匹配返回 `STALE_INDEX_BUILD_PLAN`，而不会把并发冲突包装成模糊的 503。

## 4. LLM 边界预算 / Boundary review budget

`BoundaryReviewBudget.try_acquire()` 在发起模型请求前递增。如果返回坏 JSON、HTTP 异常或模型其他失败，此次请求仍计入上限。Embedding 提供方异常使用本地 lexical cosine；LLM 失败使用 size pressure。每个 Chunk 元数据记录：

- `llm_attempted`
- `llm_calls_used`
- `fallback_reason`
- `boundary_similarity`

## 5. 上传与 OCR / Upload and OCR

Nginx 上限为 55 MiB，ASGI 上限默认为 55 MiB，单文件上限默认为 50 MiB。差额用于 multipart 边界和表单字段。端点内的 1 MiB 分块计数作为第二道文件级防线。

Docker 默认安装 OCR extra、Tesseract 中英文语言包与 CJK 字体，但是只有配置 `ENTERPRISE_RAG__OCR__ENABLED=true` 时 Worker 才自动补齐扫描页。

## 6. 端到端验收 / End-to-end acceptance

`tests/e2e/test_agentic_rag_flow.py` 使用真实 SQLite、接入 Worker、FAISS、BM25、FastAPI 和 Chat 编排器验证：

```text
TXT multipart 上传
→ 持久化任务领取与续租
→ 结构解析和切块
→ FAISS/BM25 不可变索引发布
→ 混合检索与证据评级
→ 答案生成和引用验证
```

测试只用确定性离线向量和答案适配器替代需要联网或下载权重的模型边界；如果运行环境没有真实 `faiss` 模块，测试会明确标记 `SKIPPED`，不会用假索引冒充通过。
