# V0.3 自适应切块与检索升级说明

## 目标边界

V0.3 支持 PDF、Markdown、TXT，面向企业说明书、技术资料及结构相似的规范/法典文本。系统不宣称理解任意文件；一个 Source 仍绑定一种主要 `content_profile`。

## 接入算法

```text
Loader
→ PDF 逐页完整性检测 / 可选 OCR 补页
→ PDF Reflow（页眉页脚、断行、孤立编号和标点）
→ StructureParser（标题、条款、分项、步骤、来源偏移）
→ ProfileChunkStrategy
→ AdaptiveBoundaryAnalyzer
   1. 标题/条款/步骤/警告硬边界
   2. max_tokens 硬上限
   3. BGE 向量相似度
   4. 仅模糊分数带调用 LLM JSON 复核
   5. 目标长度压力确定性回退
→ 叶子 Chunk + Token 有界父 Chunk
→ 质量门
→ 不可变索引发布
```

LLM 不决定文件是否被接受，也不能突破硬结构、最大 Token、OCR 完整性和质量门。`llm_boundary_max_calls` 在真实提供方请求前计数，所以坏 JSON 与 HTTP 异常同样消耗预算。模型输出无法解析时自动回退到长度压力，Embedding 异常则回退到本地词频余弦，都不会阻塞整份文档。

## 检索算法

- 中文连续文本生成二元词组，降低常见单字误路由。
- `第一百四十三条` 同时生成 `clause:143`，章节、步骤、错误码和型号同理。
- 标题路径和规范锚点进入 `retrieval_text`，引用仍展示 `Chunk.text`。
- Source 路由低分、并列过多或领先不足时搜索全部授权 Source。
- Dynamic Top-K 仅在确有替代文档时限制单文档数量，并去除同一父子家族重复证据。
- 引用摘录围绕实际支撑回答的局部词项生成，不再固定截取 Chunk 开头。

## 版本与重处理

每个 `DocumentVersion` 冻结：

- `content_profile`
- `chunk_strategy_id` 与 `chunk_strategy_version`
- min/target/max Token 与语义阈值
- embedding fingerprint
- 可选 LLM boundary fingerprint 与 prompt version
- 质量指标和警告

Worker 只读取版本快照。若部署后已没有该冻结策略版本，任务明确失败并要求管理员重新创建候选版本，不会静默换算法。

## OCR 完整性

原生文本页继续使用原生文本；缺少文本层的页才使用 OCR 结果。OCR 未覆盖任意缺页、平均置信度低于阈值或提供方不可用时，整个候选版本进入 `NEEDS_OCR`/`NEEDS_REVIEW`，不会发布部分页面。

本地适配器需要 `.[ocr]`、系统 Tesseract 及 `chi_sim`/`eng` 语言数据。也可按 `OCRProvider` 协议接入企业 OCR 服务。

## 民法典基线验收

至少验证以下问题集：

1. 精确条款号：第一百四十三条有哪些条件？
2. 条款内短语：与“意思表示真实”并列的条件是什么？
3. 相邻条款区分：第一百四十三条与第一百四十四条有何不同？
4. 跨页条款：条款开头和分项跨页时能否完整召回？
5. 负样本：询问文档中不存在的司法解释时是否拒答？

评估应记录 Evidence Recall、条款完整率、跨 Chunk 断裂率、引用准确率、拒答准确率、平均上下文 Token 和模型调用次数。
